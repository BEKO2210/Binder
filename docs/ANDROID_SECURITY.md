# Android security posture

An OWASP MASVS-shaped list, but only the parts that mean something for this app,
and each one answered with a file, a flag read out of the shipped artefact, or a
reason for `N/A`. Checkbox theatre is worse than nothing: it makes an untested
claim look examined.

Read against **1.0.4 (versionCode 101)**, flags taken from the merged manifest
inside the AAB, not from the source.

## Storage

| Question | Answer | Evidence |
|---|---|---|
| Where does the session live? | Encrypted at rest | `src/lib/secureSessionStorage.ts` — the token is encrypted with a 256-bit key held in `expo-secure-store` (Android Keystore); only the ciphertext goes to AsyncStorage, because SecureStore itself has a size limit a JWT can exceed |
| Can a backup carry it off the device? | No | `android:allowBackup="false"`, plus `secure_store_backup_rules.xml` and `secure_store_data_extraction_rules.xml` excluding the store |
| Drafts and unsent messages | Plain text, deliberately, and cleared with the session | `src/lib/chatDrafts.ts`, `src/lib/unsentMessages.ts`; `MenuScreen` clears both on sign-out and on deletion — the next person on this phone finds nothing |
| Remembered legal acceptance | Version- and user-scoped, cleared on sign-out | `src/lib/legalGateCache.ts` |
| Voice recordings | Temporary file, uploaded, then owned by the private bucket | `src/components/VoiceRecorderBar.tsx`, `voice-media` policies require an **active** match |

## Network

| Question | Answer | Evidence |
|---|---|---|
| Cleartext traffic | Not enabled; nothing in the manifest turns it on, and every endpoint is HTTPS | no `usesCleartextTraffic` in the manifest; no `http://` in `src/` |
| Certificate pinning | **N/A on purpose** | Supabase and Google rotate certificates on their own schedule; a pin here buys an attack nobody in this threat model is running and sells an outage nobody can fix from the store. Revisit only with a named threat |
| Signed URLs for media | 30 minutes, deliberately short | `src/lib/media.ts` — a bearer URL keeps working after a block, so it must not live long |

## Platform

| Question | Answer | Evidence |
|---|---|---|
| Release debuggable | No | `aapt2 dump badging` on the shipped APK prints no `application-debuggable` |
| Code shrinking and obfuscation | R8 on, resources shrunk | `android/app/build.gradle`; the mapping file is part of every release record |
| Exported components | Only what Android requires; the dynamic-receiver permission is generated by React Native | merged manifest of the AAB |
| Deep links | One scheme, `binder://reset-password`, `autoVerify` off | `app.json`; nothing here trusts a link's contents — `src/lib/deepLinks.ts` parses and validates, and a recovery link only ever opens the recovery screen |
| App Links (https) | **N/A** | The app claims no web domain, so there is nothing to verify |
| Logs | No `console.log` anywhere in `src/` | grep across the source tree |

## Permissions

Location (fine and coarse), microphone, notifications, biometrics, storage
read/write, vibration, wake lock, FCM. Every one traceable to a feature; the
media-playback foreground permission was removed in 1.0.1 precisely because
nothing used it.

## Not done, and named as such

- **Screenshot blocking on chat and profile screens.** `FLAG_SECURE` would stop
  the screenshots people legitimately take of their own conversations, and stops
  nothing an attacker with the device cannot do another way. Not a decision to
  make silently — written here so it is a decision.
- **Root/emulator detection.** It breaks testing and legitimate users, and stops
  nobody determined.
- **Runtime integrity checks.** Play Integrity exists and is not free of
  consequence; no evidence yet that abuse justifies it.
